## 優先修復：正在使用的功能

### 1. 抽獎持久按鈕互相覆蓋

- 檔案：`src/cogs/features/giveaway.py:35`、`:107`、`:200`。
- 所有 View 共用 `custom_id="giveaway_enter"`，但 `add_view` 未指定訊息 ID。重啟恢復多個活動時，後註冊 View 覆蓋前者的全域路由。
- 重現：依照現有方式註冊兩個活動，只剩 **1 個** persistent view。重啟後舊訊息可能被導向最後一個活動，將參加者記錄到錯誤抽獎。
- 修法：以已儲存的 `message_id` 註冊每個 View，或使 custom ID 唯一；測試多活動及重啟後的點擊路由。

### 2. 輪盤「命運洗牌」直接出錯

- 檔案：`src/cogs/games/russian_roulette.py:281`。
- 使用 `random.randint()` 卻未匯入 `random`；重現 `NameError`。道具在出錯前已從背包移除。
- 修法：補匯入，並讓失敗時不消耗道具。

### 3. 輪盤「空包彈」按使用後失去效果

- 檔案：`src/cogs/games/russian_roulette.py:259`、`:292`、`:65`；配合 `src/services/game_service.py`。
- 使用道具先移除背包項目，卻未設定減傷狀態；開槍時只檢查背包是否仍有空包彈。
- 重現：使用後立即中彈，預期剩 **4,250** 籌碼，實際剩 **3,500**。
- 修法：明確儲存玩家的已啟用減傷狀態，在命中時消耗並清除；統一被動／主動使用規則。

### 4. 訊息日誌有資料時無法清理

- 檔案：`src/services/message_log_service.py:179`。
- 未匯入 `timedelta`，空日誌會提前返回而掩蓋問題；有資料時重現 `NameError`。
- 修法：補匯入，加入有舊資料、新資料、空資料的清理測試。

### 5. 需要驗證的自動身份組無法分配

- 檔案：`src/cogs/features/management.py:777`。
- `discord.Member` 沒有 `verified` 屬性。設定 `require_verification=True` 後，成員加入流程會觸發 `AttributeError`，現有例外處理不會接住。
- 重現：使用受 `discord.Member` API 限制的 mock 執行 listener，即出錯。
- 修法：先定義「驗證」指會員篩選或其他機制；若指 Discord membership screening，應依實際狀態與更新事件處理，不能直接把不存在屬性改成永遠放行。

### 6. 重複 ready 初始化會留下背景工作

- 檔案：`src/main.py:92`、`src/utils/config_optimizer.py:95`、`src/utils/database_manager.py:315`。
- ready listener 每次重新建立管理器；舊批次寫入及資料庫清理工作未關閉。
- 重現：連續初始化兩次，工作數由 **3 增至 5**，舊工作仍存在。
- 修法：一次性初始化移到合適的生命週期，或使初始化冪等；保留 task handle 並在关闭時取消、等待完成。
- 同時修復 `src/main.py:114`：`bot.run()` 返回後才呼叫 `asyncio.create_task(network_opt.close())`，通常已沒有執行中的事件迴圈，錯誤又被忽略。應在非同步關閉流程 await 清理與批次資料 flush。此關閉項為程式流程檢查，未獨立作登入後關機測試。

### 7. 本機啟動器路徑損壞

- 檔案：`start.py:40`、`:53`，目前被 `.gitignore` 排除。
- 檔案內含實際亂碼，兩個 `Path(...)` 字串指向的資料夾均不存在；不是僅終端顯示異常。會影響使用此啟動器的方式，不代表 `python -m src.main` 也受同一問題影響。
- 修法：修復 UTF-8 內容與實際路徑，優先以啟動器所在目錄定位本專案；確認另一個 bot 的正確位置。

## 設定、CI 與版本控制問題

1. **Lint 掩蓋真實錯誤**：`.flake8:21` 與 `pyproject.toml:106` 忽略 `F401/F821/F841`。其中 `F821` 直接隱藏本次兩個 `NameError`。恢復檢查，必要例外應逐處標註；isort 整理順序不會替你移除未使用匯入。
2. **啟動測試假通過風險**：`src/bot.py` 的 `load_cogs()` 捕捉所有載入例外並只列印；`tests/test_bot_startup.py` 不驗證 extension 集合、也未關閉 Bot。本次實際 26 個都載入，但未來載入失敗仍可能綠燈。修成明確集合比對與清理。
3. **CI 尚未執行靜態品質門檻**：`.github/workflows/ci.yml` 主要跑 pytest 與 coverage 上傳，沒有對應 lint / mypy 工作，也無最低覆蓋門檻。建議先加入會攔截真實執行錯誤的檢查，再逐步處理嚴格型別債務。
4. **pre-commit 與專案工具版本落差**：`.pre-commit-config.yaml` 使用 Black 22.10、isort 5.11、Flake8 6.0、Mypy 0.991；專案依賴則已是更新版本。Flake8 hook 額外依賴還缺少 `.flake8` 要求的 `flake8-comprehensions`。本次沒有下載並執行全部 hook，列為設定待修，而非聲稱已重現 hook 失敗。
5. **尚未加入 Git**：`src/cogs/features/petition.py`、`src/services/petition_service.py`、`tests/test_services/test_petition_service.py`。本機功能與測試存在，但不會隨既有 commit 部署。確認後一起納入版本控制；本次未替你 commit。
6. **部署腳本依賴被忽略的檔案**：`register_tasks.ps1` 要求 `run_bot.bat`，但後者在 `.gitignore`。新 clone 無法直接重現此排程啟動方式；提供可追蹤模板或改由固定入口啟動。

## 證據與重跑方式

`evidence/` 保存測試、靜態分析輸出、coverage JSON、隔離用 `conftest.py` 及 `test_audit.py`。重現測試刻意期待正確行為，目前 10 個失敗是缺陷證據，不是已修復結果。

請將 `src`、`services`、`tests`、`pyproject.toml`、`.flake8` 複製到不含正式 `.env` 與資料的暫存目录，再將 evidence 中兩個 Python 測試檔放到暫存根目錄，使用專案虛擬環境 Python 執行：

```text
python -m pytest tests -v --cov=src --cov-report=json:coverage.json
python -m pytest test_audit.py -v --tb=short
python -m flake8 src services tests --isolated --select F,E9
python -m mypy src services --no-incremental --show-error-codes
python -m black --check src services tests
python -m isort --check-only src services tests
python -m bandit -r src services -f json -o bandit.json
python -m pip check
```

不要直接在正式資料目錄執行 evidence 測試：部分服務會建立相對路徑資料檔。
