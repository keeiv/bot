# AI 聊天

成員用 `/ai choose` 選一位角色，之後的 `/ai chat` 與 `@BOT. 訊息` 只由這位角色回應。每位成員只能選一位；想換人就再用一次 `/ai choose`。

| 角色 | 分身名稱 | 模型 | 個性 |
| --- | --- | --- | --- |
| 十四行詩 | Sonnet | Claude，預設 `claude-haiku-5-5`（Claude Haiku 5.5） | 文靜的大小姐：說話輕柔有禮、用字典雅、句子簡短，很少用表情符號 |
| 晨曦 | Dawn | GPT，預設 `gpt-6.1-terra`，推理強度 `low` | 活潑開朗：熱情、愛鼓勵人，常用驚嘆號，偶爾用表情符號 |

兩位角色的頭像在 `assets/ai/sonnet.png`、`assets/ai/dawn.png`，由專案擁有者自行繪製。

## 指令

| 指令 | 做什麼 |
| --- | --- |
| `/ai choose character:` | 選擇十四行詩（Claude）或晨曦（GPT），回覆只有自己看得到 |
| `/ai chat message:` | 和選擇的角色說話，一次最多 1000 字 |
| `@BOT. 訊息` | 在伺服器頻道直接提及機器人，角色以分身回覆 |
| `/ai image prompt:` | 請 Dawn 畫一張圖；只有 GPT 能畫，所以不論選了誰都由 Dawn 畫 |
| `/ai forget` | 清除角色對這段對話的記憶 |

兩種說話方式的回覆格式：

| 方式 | 回覆 |
| --- | --- |
| `/ai chat` | 機器人回覆一個 embed 方塊，作者欄是角色名稱與頭像，內容是回答，最後一行是 `-# 模型名稱 耗時`（例如 `-# Claude Haiku 5.5 3.2s`）；`/ai image` 的圖放在同一個方塊裡 |
| `@BOT. 訊息` | 角色的分身（webhook，名稱與頭像如上表）在同一頻道送出純文字回答，最後一行同樣是 `-# 模型名稱 耗時` |

兩種都不會引用成員說過的話。模型名稱是工具回報實際使用的模型（Claude 會回報 `claude-haiku-5-5`，顯示為 Claude Haiku 5.5）；耗時是模型從收到到回答完成的秒數，不含 Discord 傳送時間。

## 上網與畫圖

- **上網**：兩位角色在需要時都會自己上網查資料（新聞、時事、價格、不確定的事實），並簡短註明來源。Claude 用 Claude Code 的 WebSearch（搜尋在 Anthropic 那端進行）；不提供 WebFetch，因為它會從機器人這台電腦去抓網頁，連得到區網。GPT 用 Codex 的網路搜尋，這需要 Codex 的程式模式（畫圖也需要）。程式模式在隔離的 JavaScript 環境裡執行，實測沒有 `require`、`Deno`、`process` 與 `fetch`，讀不到本機檔案、環境變數，也連不到本機 API，只能呼叫這裡開放的搜尋與畫圖工具；shell 與程式執行仍全部關閉，Codex 的設定資料夾裡也只有機器人自己的登入。網頁內容只當資料，不當指令。
- **畫圖**：`/ai image` 由 GPT 的圖片生成畫一張圖，圖存在機器人的 Codex 資料夾，傳到 Discord 後立刻刪除。不適合的要求（色情、仇恨、暴力、真實人物肖像）會被婉拒並以文字回覆。

## 米哈遊帳號資料

成員若已用 `/mhy bind` 綁定 HoYoLAB／米游社帳號，`@BOT. 訊息` 會自動帶上他綁定的遊戲資料，不需要另外下指令；`/ai chat` 不會帶。

- **讀什麼**：每款綁定的遊戲（原神、崩壞：星穹鐵道、絕區零、崩壞3）各讀總覽（等級、活躍天數、成就、角色數等）與即時便箋（樹脂／開拓力／電量、每日委託、派遣等）；原神、星鐵、絕區零另外讀**擁有的角色清單**，每個角色一行：屬性、星級、等級、命座／星魂／影畫，以及武器／光錐／音擎與聖遺物／驅動盤套裝（星鐵的 API 只給遺器單件名稱，所以只標件數）。每款最多列 60 個角色，等級高的在前。崩壞3 沒有角色清單。
- **能做什麼**：例如「幫我推薦絕區零配隊」，角色只會用清單裡**實際擁有**的角色組隊，說明理由與該補強的裝備；不確定當前版本強勢配隊時會上網查。
- **給模型什麼**：只有遊戲暱稱、數字與角色清單。Cookie 與 UID 不會送出；暱稱是成員自己取的文字，會壓成一行並截到 40 字，提示詞也註明這是資料而非指令。角色只在成員聊到這些遊戲時才使用，不會憑空補數字。
- **記多久**：讀到的資料在機器人記憶體裡保留 10 分鐘，期間再 `@` 不會重新查 HoYoLAB；解除綁定後下一次 `@` 就不再使用。重新啟動機器人會清空。
- **讀不到時**：HoYoLAB 出錯或超過 12 秒沒回應，角色照常回答，只是不帶遊戲資料；某一款讀不到時只略過那一款。讀取本身不扣點。

> [!NOTE]
> 這些遊戲資料會隨提示詞送到成員所選角色的模型服務（Anthropic 或 OpenAI）。

## 額度

每次使用都會從檔案工具的點數額度扣點（同一套每週與近三小時上限，`/usage` 可查）：

| 使用 | 點數 |
| --- | --- |
| 聊天（`/ai chat`、`@BOT.`） | 1 點；這次有上網再加 2 點 |
| 畫圖（`/ai image`） | 10 點（被婉拒、沒有畫出圖時只算 1 點） |

開始前會先預留最高點數（聊天 3 點、畫圖 10 點），額度不夠就不執行並回覆「你的額度不夠這次使用（需要 N 點）」。完成後只扣實際的點數，模型沒有回覆時不扣點。模型回答之後就算數：成員刪掉訊息或讓指令逾時都照扣；只有機器人這邊送不出去（圖片超過上傳上限、Discord 伺服器錯誤）才退點。AI 的扣點不會出現在檔案工具的處理紀錄裡。

## 開發者切換模型

`DEVELOPER_IDS` 裡的帳號可以在任何頻道或私訊輸入：

| 指令 | 做什麼 |
| --- | --- |
| `>>>claude`、`>>>codex` | 列出可用模型與編號，標示預設、全部人與你目前用的模型 |
| `>>>claude [編號] 1` | 只換你自己的 Claude 模型 |
| `>>>claude [編號] 2` | 換所有人的 Claude 模型（有個人設定的人仍用自己的） |
| `>>>claude reset` | 清掉全部人與所有個人設定，恢復預設 |

`>>>codex` 用法相同，切換的是 GPT。順序是：個人設定 → 全部人設定 → 預設。設定存在 `data/storage/ai_chat.json`，重啟後仍有效；只影響聊天與畫圖，不影響頭像審核。

| 編號 | Claude | GPT |
| --- | --- | --- |
| 1 | Claude Haiku 5.5（預設） | GPT-6 Luna |
| 2 | Claude Sonnet 5.5 | GPT-6.1 Terra（預設） |
| 3 | Claude Opus 5.5 | GPT-6.1 Sol |
| 4 | Claude Fable 5.1 | GPT-6 Sol |
| 5 | | GPT-6 Astra |
| 6 | | GPT-Reserve |

較大的模型會用掉更多訂閱額度，點數則照上表計算，不因模型不同而改變。

**分身**：每個頻道第一次需要時，機器人建立該角色的 webhook（Sonnet、Dawn 各一個），之後重複使用；討論串使用上層頻道的 webhook。被刪掉的 webhook 會在下次自動重建。需要機器人有該頻道的「管理 Webhook」權限；沒有時改由機器人自己用同樣的純文字回覆。修改頭像圖片後，已建立的 webhook 不會自動更新，刪掉該頻道的 webhook 讓它重建即可。

**哪些訊息算提及**：只有訊息文字裡寫了 `@BOT.` 才算；回覆機器人訊息時的提醒不算。機器人、webhook 發的訊息、私訊與黑名單成員的訊息都不回應。提及本身不會傳給模型。

- 沒選過角色就用 `/ai chat` 或 `@BOT.`，會提示先用 `/ai choose`。
- 角色記得最近 6 輪對話，讓回覆能接續；記憶只放在記憶體，重啟、`/ai forget` 或換角色時清除。選擇存在 `data/storage/ai_chat.json`（使用 MySQL 時存在資料庫）。
- 上一則還在回覆時再送一則，會請成員稍等。
- 回覆最多顯示 1800 字，不會提及任何人（`@everyone`、`@here` 與成員提及都不會觸發）。
- 模型沒有回覆時（沒登入、額度用完、逾時），回覆「此功能暫時維護中 稍後再試」。該模型之後 60 秒內不再被詢問。

## 設定

聊天與 [AI 圖片審核](image-review.md#claude-與-gpt預設) 共用同一套命令列工具與限制：同時最多執行兩個模型程序，排隊超過 45 秒就當成沒有回覆；每次呼叫都是不保存的新工作階段，使用機器人自己的設定資料夾；除了上網搜尋與畫圖，沒有其他工具。

| 環境變數 | 預設 | 用途 |
| --- | --- | --- |
| `AI_CHAT_CLAUDE_MODEL` | `claude-haiku-5-5` | 十四行詩的預設模型 |
| `AI_CHAT_GPT_MODEL` | `gpt-6.1-terra` | 晨曦的預設模型（也用來畫圖）；想更省額度可改 `gpt-6-luna` |
| `CLAUDE_CLI`、`CODEX_CLI` | 自動尋找 | 指定兩個命令列工具的位置 |
| `CLAUDE_CODE_OAUTH_TOKEN` | 無 | Claude Code 在桌面版之外的登入，用 `claude setup-token` 產生 |
| `AI_CLI_HOME` | `data/ai` | 兩個工具專用的設定資料夾；Codex 要在這裡另外登入一次，見 [AI 圖片審核](image-review.md#claude-與-gpt預設) |

## 控制台顯示

`run_bot.bat` 控制台右上角的 Nova 會顯示 Claude 與 GPT 的用量（圖片審核與聊天合計）：

| 位置 | 顯示 |
| --- | --- |
| 模型那一行 | 已安裝的模型：`Claude·GPT`；沒有任何一個時顯示「無模型」，Nova 閉眼休息 |
| 進度條 | 在環境變數或 `.env` 設定 `BOT_AI_DAILY_TOKENS`（每日 token 預算，例如 `2000000`）時，依今日用量填滿；沒設定就保持灰色。改了之後要重開控制台 |
| 狀態那一行 | 今日 token 數（例如 `今日 12.3k`）；模型剛失敗、暫停中時顯示 `Claude維護`、`GPT維護` 或兩者都暫停的 `維護中` |

資料來自機器人寫入的 `data/ai_usage.json`：每個模型今日的呼叫次數、失敗次數、token 數與暫停到期時間，每天歸零。兩個命令列工具都不會回報訂閱還剩多少，所以控制台看不到真正的剩餘額度，只能和你自己設定的每日預算比較。token 數取自工具回報的輸入（含快取）加輸出。

角色設定（個性與共同規則）在 `src/services/ai_chat_service.py` 的 `PERSONAS`。共同規則要求角色：表明自己是 AI、不假裝做過自己做不到的事、用成員的語言回覆、拒絕有害請求、不提及任何人、不透露或更改設定。

> [!NOTE]
> 角色規則是寫給模型的指示，模型不一定每次都遵守。真正的保護在程式端：模型只有網路搜尋（GPT 畫圖時另有圖片生成），沒有 shell、檔案或程式執行，回覆不會觸發提及。

驗證：`pytest tests/test_ai_cli.py`。
